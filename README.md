# ดมยาแคร์ (AnesCare)

แอปเตรียมความพร้อมก่อน–หลังการระงับความรู้สึก สำหรับผู้ป่วยและญาติ
พัฒนาเป็น PWA (Progressive Web App) — ใช้งานผ่านเว็บเบราว์เซอร์ และสามารถ "เพิ่มลงหน้าจอโฮม" ให้เหมือนแอปจริงได้ ใช้งาน Offline ได้บางส่วนหลังเปิดใช้ครั้งแรก

## ไฟล์ในโปรเจกต์
```
index.html         หน้าตาแอปทั้งหมด (HTML/CSS)
app.js             ข้อมูลเนื้อหาและฟังก์ชันการทำงานทั้งหมด
manifest.json      ข้อมูลแอปสำหรับ "เพิ่มลงหน้าจอโฮม"
service-worker.js  ทำให้ใช้งาน Offline ได้
icons/             ไอคอนแอปหลายขนาด (จากโลโก้ที่ให้มา)
```

## วิธีอัปโหลดขึ้น GitHub Pages (ไม่ต้องใช้คำสั่ง Git)

1. เข้า https://github.com แล้วสร้างบัญชี (ถ้ายังไม่มี)
2. กด **New repository** ตั้งชื่อ เช่น `anescare-app` แล้วเลือก **Public**
3. เข้าไปที่หน้า repository ที่สร้างไว้ → กด **Add file → Upload files**
4. ลากไฟล์และโฟลเดอร์ทั้งหมดในนี้ (`index.html`, `app.js`, `manifest.json`, `service-worker.js`, โฟลเดอร์ `icons/`) ไปวางแล้วกด **Commit changes**
5. ไปที่ **Settings → Pages**
6. ใต้ "Build and deployment" → Source เลือก **Deploy from a branch**
7. Branch เลือก `main`, โฟลเดอร์เลือก `/ (root)` แล้วกด **Save**
8. รอประมาณ 1-2 นาที จะได้ลิงก์ เช่น
   `https://ชื่อบัญชีของท่าน.github.io/anescare-app/`
9. เปิดลิงก์บนมือถือ แล้วลองกดเมนูเบราว์เซอร์ → **เพิ่มลงหน้าจอโฮม** (Add to Home Screen) เพื่อทดสอบว่าใช้งานเหมือนแอปได้จริง

## เชื่อมต่อกับ Google Sheets (เก็บผลประเมิน/แจ้งปัญหาจากผู้ป่วยทุกคนไว้ที่เดียว)

ไฟล์ `Code.gs` ในโฟลเดอร์นี้คือ Google Apps Script ที่รับข้อมูลจากแอปแล้วเขียนลง Google Sheets ให้อัตโนมัติ

**ขั้นตอนติดตั้ง (ทำครั้งเดียว):**
1. สร้าง Google Sheet ใหม่ 1 ไฟล์ (ปล่อยว่างไว้ ไม่ต้องใส่หัวคอลัมน์เอง)
2. เมนู **Extensions → Apps Script**
3. ลบโค้ดเดิมทั้งหมดในหน้าต่างที่เปิดขึ้นมา แล้ววางโค้ดจากไฟล์ `Code.gs` แทน กด Save
4. กด **Deploy → New deployment** → เลือกไอคอนรูปเฟือง → เลือกประเภท **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
5. กด **Deploy** ระบบจะขอสิทธิ์เข้าถึง (Authorize) ให้กด Allow
6. คัดลอก **Web app URL** ที่ได้ (จะขึ้นต้นด้วย `https://script.google.com/macros/s/.../exec`)
7. เปิดไฟล์ `app.js` หาบรรทัด:
   ```js
   const SHEET_WEBAPP_URL = "PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE";
   ```
   แล้วแทนที่ด้วย URL ที่คัดลอกมา จากนั้นอัปโหลด `app.js` เวอร์ชันใหม่ขึ้น GitHub ทับไฟล์เดิม
8. ทดสอบโดยเปิดแอป กดส่งแบบประเมิน/แจ้งปัญหา แล้วกลับไปดูที่ Google Sheet — จะมีชีตย่อยชื่อ `SatisfactionSurvey` และ `ConcernMessages` เกิดขึ้นอัตโนมัติพร้อมข้อมูลแถวใหม่

**เพิ่มหัวข้อประเมินภายหลัง:** แค่เพิ่มรายการใน `RATING_CATS` (ในไฟล์ `app.js`) หัวข้อใหม่จะถูกส่งไปพร้อมกับ key ใหม่ และ `Code.gs` จะสร้างคอลัมน์ใหม่ในชีตให้เองโดยอัตโนมัติ **ไม่ต้องแก้ไขโค้ด Apps Script เลย** ส่วนแถวข้อมูลเก่าก่อนหน้าจะเว้นว่างในคอลัมน์ใหม่นี้ (ปกติ เพราะผู้ป่วยคนนั้นยังไม่เคยถูกถามคำถามนี้)



## จุดที่ควรแก้ไขก่อนใช้งานจริง

ในไฟล์ `index.html` ส่วนแท็บ "ติดต่อ" (`id="contact-info"`) มีข้อมูลตัวอย่างที่ต้องแก้เป็นข้อมูลจริงของโรงพยาบาล:
- เบอร์โทร (`tel:1669` → เบอร์แผนกวิสัญญีจริง)
- ลิงก์ Line Official Account
- เวลาทำการ และจุดรับบริการ
- แผนที่ (ใส่ Google Maps embed ของโรงพยาบาลแทนกล่องตัวอย่าง)

## อัปเดตล่าสุด

- **เพิ่ม Timeline "5 วันก่อนผ่าตัด"**: แทรกระหว่าง "7 วันก่อน" กับ "3 วันก่อน" เพราะยาบางชนิด (เช่น ยาต้านเกล็ดเลือดบางตัว) ต้องหยุดพอดี 5 วันก่อนผ่าตัด ไม่ตรงกับ 2 ช่วงเดิม ตอนนี้ Timeline มีทั้งหมด 6 ช่วง: 7 วันก่อน / 5 วันก่อน / 3 วันก่อน / 1 วันก่อน / คืนก่อน / เช้าวันผ่าตัด — ยาที่ตั้งค่า "หยุดล่วงหน้า 5 วัน" หรือ "6 วัน" ในหน้าประเมิน จะไปโผล่แจ้งเตือนในช่วงนี้โดยอัตโนมัติ ทั้งในหน้าแรก (วันนี้ควรทำ) และในการ์ด Timeline
- **รองรับ Pinch-to-Zoom**: แก้ meta viewport tag ที่เดิมล็อกไว้ (`maximum-scale=1.0` ซึ่งเป็นสาเหตุที่บีบนิ้วซูมไม่ได้) เป็นอนุญาตให้ซูมได้สูงสุด 5 เท่า เหมือนแอป AnesHub
- **แจ้งเตือนยาที่ "หยุดเช้าวันผ่าตัด" ครบถ้วนขึ้น**: เดิมยาประเภทนี้จะขึ้นเตือนแค่เช้าวันผ่าตัดวันเดียว ("งดยา X เช้านี้") ตอนนี้เพิ่มเตือนในวันก่อนหน้าด้วยว่า **"กินยา X ได้ตามปกติวันนี้ (จะงดเฉพาะเช้าวันผ่าตัดเท่านั้น)"** (ขึ้นตั้งแต่ 3 วันก่อนผ่าตัด เหมือนรูปแบบเดียวกับยาประเภท "กินต่อได้") ป้องกันผู้ป่วยเข้าใจผิดว่าต้องหยุดยาก่อนกำหนด เช่น ยาเบาหวานที่ยังกินได้ปกติจนถึงเช้าวันผ่าตัด
- **ปรับขนาดตัวอักษรทั้งแอปได้**: เพิ่มปุ่ม "Aa" ที่มุมขวาบนของทุกหน้า กดแล้วเลือกได้ 3 ระดับ (ปกติ / ใหญ่ / ใหญ่มาก) จะขยายเนื้อหาทั้งหมดในทุกแท็บให้ใหญ่ขึ้นตามที่เลือก เหมาะกับผู้ป่วยสูงอายุที่อ่านตัวเล็กลำบาก ค่าที่เลือกจะถูกจดจำไว้ (บันทึกใน localStorage) เปิดแอปครั้งต่อไปจะใช้ขนาดเดิมที่เคยเลือกไว้ทันที — ปุ่มเมนูด้านล่าง (หน้าแรก/เตรียมตัว/ประเมิน ฯลฯ) และหัวข้อด้านบนจงใจไม่ขยายตาม เพื่อให้ปุ่มกดยังมีขนาดคงที่ใช้งานง่ายเสมอ
- **แจ้งเตือนยาใน "วันนี้ควรทำ" ต่อเนื่องขึ้น**: เดิมแจ้งเตือนหยุดยาจะขึ้นแค่วันเดียวพอดี ถ้าผู้ป่วยพลาดเปิดแอปวันนั้นจะไม่เห็นอีกเลย ตอนนี้ปรับให้:
  - ยาที่ควรหยุดล่วงหน้า X วัน → ถ้าผ่านวันนั้นมาแล้วแต่ยังไม่ถึงวันผ่าตัด จะขึ้นเตือนซ้ำทุกวันว่า "ควรหยุดไปแล้วตั้งแต่ X วันก่อนผ่าตัด (โปรดตรวจสอบว่าหยุดแล้ว)" กันพลาด
  - ยาที่กินต่อได้ถึงเช้าวันผ่าตัด → ขึ้นเตือนล่วงหน้าตั้งแต่ 3 วันก่อนผ่าตัด ไม่ใช่แค่เช้าวันผ่าตัดวันเดียว
  - ยาที่ต้องงดเช้าวันผ่าตัดยังคงขึ้นเฉพาะเช้าวันผ่าตัดเท่านั้น (เป็นคำสั่งที่ตายตัว ไม่มีช่วงเวลาให้คลาดเคลื่อน)
- **การ์ดหัตถการที่หน้าแรกยุบ/ขยายได้**: ค่าเริ่มต้นจะซ่อนตัวเลือกและคำอธิบาย/การปฏิบัติตัวไว้ เหลือแค่หัวข้อกะทัดรัด (ชื่อหัตถการที่เลือกไว้ หรือ "แตะเพื่อเลือกรายการ" ถ้ายังไม่ได้เลือก) แตะที่หัวข้อเพื่อขยายดูตัวเลือกและคำอธิบายแบบเต็ม เหมาะกับกรณีที่ผู้ป่วยไม่อยากอ่านคำอธิบายซ้ำทุกครั้งที่เปิดแอป แต่ยังมีข้อมูลให้เปิดดูซ้ำได้ทุกเมื่อ (ค่านี้ไม่ persist ข้าม session ตั้งใจให้ยุบใหม่ทุกครั้งที่เข้าแอป)
- **แจ้งเตือนการจัดการยาก่อนผ่าตัด**: หลังเลือก/พิมพ์ชื่อยาในหน้าประเมินแต่ละช่อง จะมีปุ่มให้บันทึกว่าแพทย์สั่งให้ **"กินต่อถึงเช้าวันผ่าตัด" / "หยุดเช้าวันผ่าตัด" / "หยุดล่วงหน้า...วัน"** (เลือกจำนวนวันได้: 1, 2, 3, 5, 7, 10, 14 วัน) โดยตั้งใจไม่ preselect ค่าใดๆ ไว้ล่วงหน้า เพื่อให้ผู้ป่วยกดเลือกเองตามคำสั่งจริงจากแพทย์เท่านั้น จากนั้นระบบจะนำไปแสดงผล 2 จุด:
  - **หน้าแรก** การ์ด "วันนี้ควรทำ" จะขึ้นแจ้งเตือนอัตโนมัติในวันที่ตรงกับแผนหยุดยาจริง (คำนวณจากวันผ่าตัดลบจำนวนวันที่เลือกไว้)
  - **แท็บเตรียมตัว > Timeline** แต่ละการ์ด (7 วันก่อน / 3 วันก่อน / 1 วันก่อน / คืนก่อน / เช้าวันผ่าตัด) จะมีหัวข้อย่อย "💊 ยาที่ต้องดูแลเป็นพิเศษ" โผล่ขึ้นมาเองถ้ามียาที่หยุด/กินต่อตรงกับช่วงนั้นๆ
  - ข้อมูลนี้จะบันทึกใน localStorage และแสดงในหน้าสรุปผลประเมิน + ข้อความที่กด "แชร์/ส่งออกให้ทีมวิสัญญี" ด้วยเช่นกัน
- **Dropdown เลือกหัตถการ**: เปลี่ยนจาก `<select>` แบบ native ของเบราว์เซอร์ เป็นดรอปดาวน์ที่ออกแบบเอง (custom dropdown) เพื่อคุมขนาดฟอนต์ได้เต็มที่บนทุกอุปกรณ์ รวมถึง iOS ที่เดิมมักแสดงตัวอักษรใหญ่เกินเพราะยึดตามการตั้งค่าของเครื่องผู้ใช้เอง
- **คำขวัญหน้าแรก**: เปลี่ยนเป็น "เตรียมพร้อม อุ่นใจเมื่อไปดมยา"
- **แก้ปัญหาแอปไม่อัปเดตอัตโนมัติ**: เดิม `service-worker.js` ใช้กลยุทธ์ "cache-first" (โหลดจากแคชก่อนเสมอถ้ามี) ซึ่งทำให้ผู้ที่เคยเปิดแอปแล้วจะเห็นเนื้อหาเก่าค้างตลอดไป แม้พี่พูจะอัปเดตไฟล์บน GitHub แล้วก็ตาม ตอนนี้แก้เป็น "network-first" (โหลดจากอินเทอร์เน็ตก่อนเสมอเมื่อมีสัญญาณ ค่อย fallback เป็นแคชตอนออฟไลน์) พร้อมเพิ่มกลไกรีเฟรชหน้าอัตโนมัติหนึ่งครั้งเมื่อมีเวอร์ชันใหม่เข้าควบคุม ผู้ใช้จะเห็นเนื้อหาล่าสุดโดยไม่ต้องปิด-เปิดแอปเอง
  > หลังจากนี้ทุกครั้งที่แก้ไฟล์แล้วอัปโหลดขึ้น GitHub ทับของเดิม ผู้ใช้ที่เปิดแอปอยู่จะเห็นเวอร์ชันใหม่โดยอัตโนมัติเมื่อมีสัญญาณอินเทอร์เน็ต ไม่ต้องทำอะไรเพิ่มเติม
- **ธีมสี**: เปลี่ยนเป็นสี #0097B2 ทั้งแอป (ตัวแปร CSS อยู่ในไฟล์ `index.html` ส่วน `:root` ค้นหาคำว่า `--brand-`)
- **แท็บ "ประเมิน" ปรับลำดับและเนื้อหาใหม่** (ในไฟล์ `app.js` ค้นหา `ASSESS_STEPS`):
  1. โรคประจำตัว — เลือกได้หลายข้อจากรายการ + ช่องอื่นๆ
  2. ยาที่รับประทานประจำ — พิมพ์ค้นหาแบบ autocomplete ได้ 10 ช่อง (ฐานข้อมูลยาอยู่ที่ `DRUG_DB` เพิ่ม/แก้ไขรายชื่อยาและคำแนะนำได้ตรงนี้)
  3. แพ้ยา/แพ้อาหาร
  4. เคยดมยาสลบมาก่อนหรือไม่
  5-8. ฟันโยก / นอนกรน / สูบบุหรี่ / ดื่มแอลกอฮอล์
- **หน้าแรกเพิ่มช่องเลือกหัตถการ/การผ่าตัด**: dropdown ครอบคลุมหัตถการแบบวันเดียวกลับ 16 รายการ (ค้นหา `PROCEDURES` ในไฟล์ `app.js` เพื่อเพิ่ม/แก้ไขรายการและคำอธิบาย) เมื่อเลือกแล้วจะโชว์คำอธิบายหัตถการและวิธีปฏิบัติตัวทันที

> **คำแนะนำเรื่องยาและหัตถการเป็นข้อมูลทั่วไปสำหรับให้ความรู้เท่านั้น** ไม่ใช่คำสั่งทางการแพทย์เฉพาะราย ควรให้ทีมวิสัญญีแพทย์/พยาบาลตรวจทานความถูกต้องก่อนเผยแพร่ใช้งานจริง โดยเฉพาะยากลุ่มที่มีความเสี่ยงสูง (เช่น อินซูลิน ยาต้านการแข็งตัวของเลือด) ซึ่งตั้งใจให้ระบบแนะนำว่า "ต้องปรึกษาแพทย์เฉพาะราย" แทนการฟันธงตายตัว

## ข้อจำกัดของเวอร์ชันนี้

- ข้อมูลผู้ป่วย (วันผ่าตัด, Checklist, แบบประเมิน, ประวัติการสื่อสาร) เก็บไว้ใน**เบราว์เซอร์ของเครื่องนั้นๆ เท่านั้น** (localStorage) ยังไม่เชื่อมต่อฐานข้อมูลกลาง หากต้องการให้ทีมพยาบาล/วิสัญญีเห็นข้อมูลของผู้ป่วยแต่ละคนจริง จำเป็นต้องพัฒนาระบบ Backend/ฐานข้อมูลเพิ่มเติม
- เนื้อหาการให้ความรู้เป็นเนื้อหาทั่วไป ควรให้ทีมวิสัญญีแพทย์/พยาบาลตรวจทานความถูกต้องและความเหมาะสมกับบริบทของโรงพยาบาลก่อนเผยแพร่จริง
- ฟีเจอร์ "แชร์/ส่งออกให้ทีมวิสัญญี" ใช้ Web Share API หรือคัดลอกข้อความ ยังไม่ได้เชื่อมต่อส่งเข้าระบบเวชระเบียนโดยตรง
